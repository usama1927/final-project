Software Requirements Specification (SRS)

Automatic Voice-Based Assessment System for Visually Impaired Learners

Using Django Backend + Django Templates Frontend


---

1. Introduction

1.1 Purpose

This Software Requirements Specification (SRS) defines the functional, non-functional, technical, and system requirements for an AI-powered, voice-based assessment platform designed for visually impaired learners.

The system enables students to complete academic assessments using their voice while receiving real-time transcription, scoring, and feedback.

The backend is developed in Django, and the frontend uses Django Templates, ensuring accessibility, security, and compatibility across devices.


---

1.2 Scope

The system provides:

Voice-based question delivery

Speech-to-text transcription via ASR (Whisper or Wav2Vec2)

NLP-based answer evaluation (BERT models)

LLM-generated structured feedback

Accessible UI designed for visually impaired users

Admin panel for teachers to upload questions, view results, and generate reports


The system supports:

Audio navigation

Minimal visual dependency

WCAG 2.1 AA accessibility compliance

3. System Features (Functional Requirements)

3.1 User Authentication

FR-1: The system must allow user login via username + password.
FR-2: Each user is assigned a role (Student / Teacher).
FR-3: Teachers have admin access through Django Admin.


---

3.2 Assessment Management (Teacher Dashboard)

FR-4: Teachers can create assessments with:

Title

Subject

Questions (text or audio)

Rubrics


FR-5: Teachers can view student's attempts, scores, WER, and feedback.
FR-6: Teachers can download CSV/PDF summaries.


---

3.3 Voice-Based Assessment Interface (Student)

Assessment Flow

1. System reads the question aloud.


2. User speaks the answer.


3. ASR transcribes the answer.


4. NLP evaluates semantic correctness.


5. LLM generates feedback.


6. System plays audio feedback.



FR-7: Student must be able to start/stop recording.
FR-8: System must provide audio navigation commands:

“Repeat”

“Go back”

“Next question”

“Help”


FR-9: ASR must transcribe answers in real time.
FR-10: System must display transcription (optional toggle).


---

3.4 ASR Processing

FR-11: System supports Whisper OR Wav2Vec2 as ASR backend.
FR-12: Fine-tuned models must be used if available.
FR-13: System must compute word error rate (WER) per attempt.


---

3.5 Automated Scoring & NLP Processing

FR-14: NLP engine evaluates:

Semantic similarity

Coverage of expected concepts

Coherence


FR-15: Scores range from 0–100.
FR-16: Scoring must use rubric-based evaluation prompts for consistency.


---

3.6 Feedback Generation

FR-17: Feedback must be LLM-generated using structured prompts.
FR-18: Feedback must be converted to audio via TTS.
FR-19: Feedback must be stored in the database for teacher review.


---

3.7 Accessibility Features

FR-20: UI must follow WCAG 2.1 AA.
FR-21: System must support complete audio navigation.
FR-22: Keyboard-only mode must be available.
FR-23: Pages must be fully screen-reader compatible.


---

3.8 System Logging

FR-24: Log WER, scoring, model version, latency, and errors.
FR-25: All logs must be visible to admin only.


---

4. Non-Functional Requirements (NFR)

4.1 Performance

ASR response < 2 seconds

LLM feedback < 4 seconds

System supports 200 concurrent users



---

4.2 Security

JWT-based session handling

End-to-end encrypted audio uploads

GDPR-compliant storage

Role-based access control

Voice data must never be shared without consent



---

4.3 Usability

Every action must have an audio equivalent

Simple two-button UI: Record and Next

Large, high-contrast controls



---

4.4 Reliability

System uptime ≥ 99%

Fail-safe mechanism:

If ASR fails → ask student to repeat

If NLP fails → perform fallback rule-based scoring
